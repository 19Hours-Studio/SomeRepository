# v4: движок сам вызывает модель — одним проходом и с бюджетом токенов

## Зачем
До v4 движок был наполовину ручным: `ce.py` собирал промпты и разбирал ответы, а каждого агента запускал я. Это
дорого и плохо повторяется. Каждый шаг был субагентом Claude Code, и даже генератор без инструментов стоил
90–170 тыс. токенов: системный промпт, описания инструментов, цикл вызовов.

## Что сделано
- `engine/runner.py`: шаг идёт через headless `claude -p` со своей моделью, набором инструментов и бюджетом
  (`--max-budget-usd`). Токены и цена каждого шага пишутся в `runs/<R>/usage.jsonl`.
- `ce.py exec R --prompt <файл> --label L [--model opus] [--tools none|research|...] [--ingest-arm A]` — один шаг.
- `ce.py usage R` — токены и цена по шагам и всего.
- `ce.py plan R --pipeline explain --mode lite|standard` — шаги и оценка токенов до запуска. Оценки заменяются
  средними самого прогона, когда они накопятся.
- `ce.py run R --pipeline explain --mode lite|standard --max-tokens N [--notes ...]` — весь конвейер «объясни
  загадку» одним проходом:
  1. реестр фактов и прежние объяснения;
  2. 3 генератора;
  3. слепой разбор;
  4. только в standard: эволюция под разбором и повторный разбор;
  5. починка с поиском;
  6. финальный слепой разбор и победитель.

  Можно продолжить с места остановки: готовые шаги пропускаются. Шаг, который превысит бюджет, не запускается.
- Тест без моделей: `CE_FAKE_LLM=<файл>` подставляет ответ, `test_ce.py` прогоняет весь конвейер.

## Дальше (по ожидаемой отдаче)
1. Тот же `run` для изобретательских вопросов: потолки по бухгалтерии до генерации → генерация с бухгалтерией и
   прежними попытками → тест на смерть с набором расчётов → починка → слепой аудит → сборщик цепочек.
2. Шаг «измерить или смоделировать»: скрипты, а не агенты. На загадке так сделаны 3D-обмер и симуляция бросков.
3. Строгость аудита: убийца, построенный на допущении по умолчанию, — WOUNDED с решающей неизвестной; второй
   аудитор только при расхождении.
4. Полигон с известными ответами, чтобы мерить улучшения движка, на дешёвом режиме lite.
5. Память между прогонами: классы убийц, удачные приёмы, найденные аудитом факты.

## Второй замер: шаг с инструментами (проверка экзамена по додекаэдру, Opus, поиск + Python)
`ce.py exec ... --tools research`: **607 419 токенов, $1.35, 4 мин, 20 поисков.** Почти все токены — повторное
чтение контекста на каждом ходу (cache re-reads). Промпт был большой (экзамен плюс весь реестр фактов, ~4.6 тыс. слов),
и он перечитывался ~80 раз. Вывод: **шаг с инструментами через headless-вызов сам по себе не дешевле.** Его цена ≈
размер контекста × число ходов. Что с этим делать:
- давать шагу короткий промпт: только нужные факты, а не весь реестр;
- ограничивать число поисков (задание просило не больше 25);
- для проверочных шагов брать Sonnet;
- в `ce.py usage` теперь видно, сколько токенов пришлось на повторное чтение.

Шаги без инструментов (генераторы) остаются в ~7 раз дешевле субагентов.
