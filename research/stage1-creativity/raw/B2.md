Each proposal replaces the core loop of next-token prediction over a fixed context window with a different computation.

=== IDEAS ===
IDEA 1
NAME: Consolidating episodic-semantic memory architecture
MECHANISM: A fast sparse episodic store writes each experience in one shot, with no gradient step, so new information is retained immediately. A slow network is trained offline by replaying samples from that store and distilling them into its weights, after which the consolidated traces are pruned. Retrieval is sparse and indexed, so per-step cost does not scale with total history length.
DIFFERENCE: It retains and updates knowledge from single exposures indefinitely without context growth or retraining, which a frozen-weight, fixed-window model cannot do.

IDEA 2
NAME: Interventional causal world-simulator
MECHANISM: The model maintains an explicit, editable causal graph over latent variables, where each edge is a small learned mechanism. When a prediction fails, it chooses an intervention to run and updates only the edges that the observed surprise implicates. Answering a "what if" query means performing graph surgery on the chosen variable and simulating forward.
DIFFERENCE: It answers interventional and counterfactual questions by construction, whereas models trained on observational text cannot separate correlation from the effect of an action.

IDEA 3
NAME: Verified program-library reasoner
MECHANISM: Rather than emitting answers directly, the model proposes candidate programs in an executable language, runs them in a sandbox, and keeps only those that pass a checker. Verified programs go into an embedding-indexed library, and new problems are solved by retrieving and composing library entries. The proposer is trained on successes, so the library grows without retraining the whole system.
DIFFERENCE: Its outputs carry a machine-checked certificate on checkable tasks, and its knowledge accumulates as auditable, reusable procedures that a single forward pass can neither verify nor store as code.
