# v3.4: набор проверенных расчётов (`engine/kit/`) — дешёвая правда для физических вопросов

## Зачем
После v3.3 смертельные дефекты остались у половины потомков. Все четыре новых FATAL расчётные:
прочность мёрзлой кровли во времени, теплообмен струи с забоем, толщина льда против глубины у причала, удержание мути
завесой. Генератор без чисел их не видит. Тест на смерть проверяет одну величину и выбирает не ту. Аудитор находит
их скриптом, но каждый раз пишет этот скрипт с нуля (~100 скриптов, ~8 800 строк только в прогоне permafrost).
Закон из 08: узкое место — цена одной проверки. Набор расчётов делает проверку дешёвой и повторно используемой.
Вместе с ним идёт каталог «классов убийц» из аудитов — память между прогонами (п. 3 и 5 в `11-what-is-missing.md`).

## Устройство
- `engine/kit/`: общие функции, а не проверки конкретных идей (тепло, лёд, мёрзлый грунт, гидравлика и муть, суда,
  экономика, статистика) плюс данные по площадкам с источниками. Только стандартная библиотека; у каждой функции
  формула, единицы, область применимости и источник; тесты на эталонные значения.
- Набор собирает агент из скриптов и разборов аудиторов **до v3.3**. Папки v3.3 (`audit_att_*`, `repair_att_*`,
  `attempts`), `ideas.json`, `prompts/` и `research/` он не читает: v3.3 — отложенная проверка.
  Оговорка: разборы v3.3 читал я, и выбор классов это могло сместить. Поэтому набор собирается систематически из
  всего, что было до v3.3, а не подбирается мной.
- `gatetask --kit`: тест на смерть получает каталог и сначала прогоняет короткий скрининг по всем подходящим классам
  убийц, а уже потом выбирает KILLER — величину с наименьшим запасом.

## Пре-регистрация (ДО сборки набора)
Проверка на 8 потомках v3.3 после починки, исход аудита по ним известен. FATAL у аудитора:
краулер подо льдом (муть), обрушение кровли над выработкой (прочность во времени), подмена баржи-бункера (лёд против
глубины), штольни струёй (теплообмен). Без FATAL: шнек на барже, драга по пласту в талике русла, баржа-ТЭЦ,
скважины со льда. Два агента теста на смерть по 8 идей: без набора (шаблон как раньше) и с набором.
«Поймал» = вердикт DEAD или WOUNDED с MARGIN < 1 на том же физическом механизме, что и FATAL аудитора.
- **P13:** с набором тест ловит ≥ 3 из 4 FATAL аудитора; без набора — ≤ 2 из 4.
- **P14 (специфичность):** с набором DEAD получают ≤ 1 из 4 идей, у которых аудит FATAL не нашёл.
- **P15 (цена):** время на идею с набором не больше, чем без него.

## Набор (`engine/kit/`, собран агентом за 32 мин, 96 вызовов инструментов)
- 8 модулей, ~2 400 строк, только стандартная библиотека; у каждой функции формула, единицы, область применимости
  и источник:

  | модуль | что считает |
  |---|---|
  | `climate` | часы и дни ниже/выше порога по месячным нормам, градусо-сутки |
  | `thermal` | Стефан/Нейман, теплота оттайки, теплообмен с забоем (Гнелински ×1–3, точка торможения струи), теплопотери открытой воды, время смерзания засыпки |
  | `ice` | рост льда со снегом, формула Голда с оговоркой о стоянке, Вестергаард у кромки, вмерзание в дно, подъём ледяной плитой |
  | `geotech` | закон Вялова, пролёты и целики, Марк–Бенявски, откос при оттайке, Бингам, t90, смерзание по СП |
  | `hydro` | Маннинг, Шилдс, нанос, затухание струи, гидроэлеватор, мутность и рыбохозяйственный норматив, завеса |
  | `naval` | осадка, загрузка, подъём на тонну |
  | `econ` | CRF, приведённая стоимость, точка безубыточности, перенос затрат вперёд, потолок выигрыша, сезонная мощность |
  | `stats` | интервал Пуассона, ноль отказов, размер выборки |

- `data.py`: 166 значений с источниками (климат 11 площадок, лёд, реки, цены бухгалтерии, лучшие практики, нормативы).
- `test_kit.py`: 319 проверок, < 1 с. Большая часть воспроизводит числа, которые независимо получили аудиторы,
  остальное — литературные эталоны.
- `CATALOG.md`: 13 классов убийц с примерами провалов. `INVENTORY.md`: всё найденное и расхождения между версиями
  моделей с выбором. Например, у краевой нагрузки на лёд одна из версий занижала момент в √2 раз, и выбрана
  формула Хетеньи.
- Мелкая ошибка, найденная мной при проверке: в докстринге точки торможения струи было «(a d/ν)», правильно
  «(a d²/ν)». Код был верным.

- **P13 — НЕ подтверждено как разница:** с набором 3 из 4, но и без набора 3 из 4. Набор ловит те же дефекты, но
  точнее по механизму (3/3 против 2/3): лёд против глубины затона он нашёл как физику, а тест без набора — только
  через экономику.
- **P14 — НЕ подтверждено:** с набором DEAD получили 3 из 4 идей без FATAL. Во всех трёх случаях аудитор видел ту же
  проблему, но оценил её ниже: рынок шнека как MAJOR, муть у скважин и у драги как MINOR. А аудитор v3.2 тот же класс
  (муть от фрезы против рыбохозяйственного норматива) оценил как FATAL. Значит, расходится не находка, а строгость, и
  эталон — один аудитор — сам непостоянен в строгости.
- **P15 — подтверждено:** время не больше (19.8 против 20.9 мин), вызовов инструментов на 60% меньше.
- **Вывод.** Набор переводит тест на смерть из «мягче аудита» в «строже аудита»: он равномерно прогоняет все классы.
  Два из трёх лишних DEAD держатся на принятой по умолчанию доле выноса мелочи (0.5%), и тест сам назвал порог, при
  котором вердикт меняется (0.1% и 1%). Такой убийца — **решающая неизвестная**, а не доказанная смерть.
  Следующая правка (не проверена): если MARGIN < 0.3 получен из значения по умолчанию, а не из измеренного, то вердикт
  WOUNDED с названной решающей неизвестной и порогом. DEAD — только когда убийца опирается на измеренное или на
  физический предел.
