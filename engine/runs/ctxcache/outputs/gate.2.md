IDEA 1: Edits become appended patches
KILLER | mid-document edits per 10-question session needed for the claimed ≥1.5× saving in archetype C | required 2.7 edits/session | available ≈1 edit/session (the ledger says "sometimes edited"; I found no measured edit-rate data) (exact arithmetic in gate_calc.py: the extra cost of rewriting the 25k suffix after an edit is $0.086 against $0.005 for a patch, and the base session costs $0.42) | MARGIN 0.37
CHAIN | Anthropic prefix cache with a breakpoint after the document, rewriting the suffix after each edit (archetype C) | now $0.51/session (1 edit) | with idea $0.43/session | RATIO 1.19 (1.10 at 0.5 edits, 1.56 at 3 edits; about 1.0 in archetype A, because coding agents already append edit results as new tool output instead of rewriting earlier reads)
VERDICT | WOUNDED | The arithmetic holds, but the saving only appears in sessions with about 3 or more mid-document edits, and the quality cost of reading stale text plus a patch (instead of clean text) has not been measured on a real model.
NEW FACT | PI-LLM: when a model is given a stream of updates to the same key, its accuracy at retrieving the latest value falls log-linearly toward zero as updates pile up, the errors are earlier overwritten values, and prompt fixes like "ignore earlier input" help little. This is direct evidence against keeping stale text alongside patches. | [arXiv 2506.08184](https://arxiv.org/abs/2506.08184)

IDEA 2: Append-patch history with stubbing
KILLER | average context after stubbing (the read reduction) | required ≈25k tokens (a 2.4× read cut, the idea's own figure) | available 43k tokens (a 1.38× read cut) when replaying archetype A (20k fixed base, 2k/turn of which 1.4k is tool output, stub every 10 turns while keeping 5); the 1.25× rewrites add $0.205 per task, which cancels the $0.196 read saving (gate_calc.py) | MARGIN 0.58
CHAIN | Anthropic's built-in context editing (`clear_tool_uses` with `clear_at_least`), or observation masking, which is already shipped practice | now $1.38/task (plain append-only: also $1.38) | with idea $1.39/task | RATIO 0.99 (even taking the idea's 2.4× read cut as given: about 1.18)
VERDICT | DEAD | The rewrite writes cancel the read savings, and the mechanism itself already exists as Anthropic context editing and JetBrains-style observation masking.
NEW FACT | Observation masking in SWE-agent on SWE-bench Verified was 52% cheaper than the raw agent and raised the solve rate by 2.6 points (Qwen3-Coder 480B). That is about 2× cheaper than a raw agent, but it is prior art. | [arXiv 2508.21433](https://arxiv.org/abs/2508.21433)
NEW FACT | Anthropic's docs say clearing tool results breaks the cached prefix, incurs a fresh cache write, and recommend `clear_at_least` so the invalidation is worthwhile. This is the same trade-off the idea relies on, and it is already a product feature. | [docs.claude.com context editing](https://docs.claude.com/en/docs/build-with-claude/context-editing)

IDEA 3: Append-only patch log
KILLER | answer accuracy when the model reads the original text plus N accumulated patches, compared with clean rewritten text, up to the compaction threshold ε | required ≤1 point of accuracy loss at N≈3–20 (patching only beats a 25k×1.25 rewrite after several edits) | available: not measured on a real model; the nearest evidence (PI-LLM) shows a monotonic log-linear decline as updates accumulate, with limited prompt fixes; economically it is the same bound as Idea 1 (2.7 edits/session needed, ≈1 seen) | MARGIN ≈0.4 (economic bound; the quality part needs a real-model run, e.g. a document-QA set with 1/3/10/30 patches against a clean rewrite)
CHAIN | prefix cache with a suffix rewrite on each edit (archetype C) | now $0.51/session | with idea $0.43/session | RATIO 1.19
VERDICT | WOUNDED | It is nearly the same idea as Idea 1 but without a cost-based compaction rule. The saving needs frequent edits, and frequent edits are exactly where PI-LLM-type interference grows.
NEW FACT | PI-LLM's dataset covers 1–46 keys with 1–400 updates per key, and the README says GPT-5, Grok-4 and Gemini also fail to retrieve the final value reliably. | [arXiv 2506.08184v3](https://arxiv.org/html/2506.08184v3)

IDEA 4: Deviation-gated chunk KV reuse
KILLER | recompute fraction that keeps quality equal to full recompute | required ≤10% (the idea's condition for 0.2× uncached input) | available 10–15% (CacheBlend's operating point with F1 within ~0.02; [LMCache blog](https://blog.lmcache.ai/2025-03-31-eurosys), [arXiv 2405.16444](https://arxiv.org/pdf/2405.16444)); one counter-report says approximate KV matching loses 9–11 points (about 60%→50%) on MultihopRAG with Llama3.3-70B and Qwen3-32B, and that KV deviation does not reliably indicate reusability ([ContextPilot, arXiv 2511.03475](https://arxiv.org/pdf/2511.03475)) | MARGIN 0.67 (10/15). Memory and bandwidth are fine: 160 KiB/token in FP8 is exact for Llama-70B (80 layers × 8 KV heads × 128 dims × 2 for K and V), about 0.98 GB per 6k tokens, about 0.1 s at 10 GB/s against about 1.06 s for a full prefill
CHAIN | own stack: vLLM + LMCache prefix caching with offload (archetype D) | now 1.00 cost units/request | with idea 0.53 (10% recompute + 2% calibration sample + 2% load overhead) | RATIO 1.90 (B, provider-side, if passed through in price: 2.3–2.5; against CacheBlend already in LMCache: 1.03)
VERDICT | WOUNDED | Most of the gain is CacheBlend's, which already exists. The ≤10% recompute target is not shown, and a first-token-KL gate may not catch multi-hop accuracy loss, which is the failure ContextPilot reports.
NEW FACT | EPIC (ICML 2025) recomputes only around each chunk's start (the attention sink) instead of about 15% of tokens, and reports up to 8× TTFT and 7× throughput with "negligible or no" accuracy loss. This is prior art that already goes below 15% recompute in an open-loop way. | [EPIC, PMLR v267](https://proceedings.mlr.press/v267/hu25j.html)
NEW FACT | The ledger's source arXiv 2511.03475 is ContextPilot, a context-reuse system that argues against approximate KV matching. | [arXiv 2511.03475](https://arxiv.org/pdf/2511.03475)
