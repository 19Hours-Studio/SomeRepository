Against the best current practice, the answer supports no gain at bulk speeds. Its one gain is a modelled, unmeasured 1.4× in output tok/s per watt over Rubin NVL72 at ≥1,000 tok/s/user. That gain mostly disappears against Rubin Ultra, the rival due when Continuum could ship.

**The code checks out.** I reran all seven round-7 scripts and each output matched its saved file exactly. The answer's tables match `run7d.txt`, and the hand arithmetic in §4.2 (22.8 vs 18.6 PF/kW, giving 1.17×) is correct. The answer is also honest about its limits: it doesn't claim "best in the world", says the bulk tier is a tie, and admits it loses to Ultra at Nvidia's 600 kW figure.

**Where the headline numbers shrink.** These come from my probe, `probe_same_node_vs_ultra.py`, using the answer's own model. Figures are tok/s per watt as a ratio, at 128K context.

| Comparison | ≥200 tok/s/user | ≥1,000 tok/s/user | ≥2,000 tok/s/user |
|---|---|---|---|
| Headline vs Rubin | 1.17 | 1.57 | 2.47 |
| Same process node vs Rubin | 1.06 | 1.42 | 2.25 |
| Same node, tile efficiency 0.5, vs Rubin | 0.88 | 1.19 | 1.87 |
| Same node vs Rubin Ultra (power estimated from its parts) | 0.93 | 1.03 | 1.08 |
| Same node, tile efficiency 0.5, vs Rubin Ultra | 0.78 | 0.86 | 0.90 |

1. **The bulk-speed gain comes from the process node, not the design.** Continuum gets credit for TSMC N2 against Rubin's N3P. On the same node the gain is 1.06×, and below 1× if tile efficiency is 0.5. A 2028 Nvidia part would be on N2 or A16 as well.
2. **The fair rival is Rubin Ultra.** Continuum ships in 2028 at the earliest, and SemiAnalysis reportedly says Ultra's Kyber rack has slipped to 2028 too. On the same node, with the same undervolting rules for both, the result is a tie (0.93–1.08×) at 128K. At 1M context it loses below 1,000 tok/s/user (0.82×).
3. **The calibration doesn't anchor the model.** The measured GB300 figure is either 0.19× or 1.70× the model's prediction. That depends on whether InferenceX counts input tokens, which nobody has confirmed. The calibration rows also don't change with draft acceptance or latency, because the model picks no speculative decoding while the measured run used it. No Continuum figure is tied to any measurement.
4. **What does hold up:** 3–4× more tokens per HBM stack. That is simple arithmetic, since the weights sit in on-chip SRAM. The cost is about 1.4× more leading-edge logic area per token and a lot of scarce hybrid-bonding (SoIC) capacity per GW.
5. **The Rubin+LPX baseline is weak, but for a physical reason, not a code bug.** The model puts it about 7× below plain Rubin. That follows from holding FP8 weights in 0.5 GB SRAM chips, which takes about 3,500 LP30s for this model. It still contradicts Nvidia's projected "up to 35× per MW" claim, so the 8–11× figures shouldn't be read as a real-world ranking.
