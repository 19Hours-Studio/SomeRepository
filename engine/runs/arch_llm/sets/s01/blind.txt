A01
MECHANISM: A briefly trained 120M trunk is frozen, and above it sits a head of 4096 cells, each a 512×256 linear map. Each token is routed to one cell by k-means on the trunk state, and every cell maps into a shared 256-d vocabulary factor taken from a PCA of a 1.5B open model's logits. The head is trained in one streaming pass: for each token, the GPU adds rank-1 updates to that cell's normal equations (XᵀX, and XᵀY where Y is the teacher's logits in the PCA basis), which take about 6 GB. The cell unknowns are removed by Schur complement onto the shared factor, which is solved by Cholesky; the cells are then back-substituted, and two or three such alternations replace SGD entirely.
VALUE: The head reaches the exact least-squares optimum without backward passes, learning rates or activation memory, so it takes in several times more tokens per week than a backprop-trained model of the same size.

A02
MECHANISM: The context is split into 64-token chunks grouped into GOPs. I-chunks keep their full fp16 K/V. Each P-chunk stores, per head, a motion vector (a reference chunk plus token alignment, found by matching key sketches) and a quantized low-rank residual. An encoder chooses between I and P coding and sets the residual rank by Lagrangian rate-distortion optimization, with distortion measured as attention-output error on probe queries. Attention rebuilds P-chunks from their references in shared memory, so the GPU mostly reads small residuals.
VALUE: Repetitive material such as code, logs and long documents gets million-token working memory in 12 GB, with every token still exactly addressable where a same-budget transformer would have to truncate or evict.

A03
MECHANISM: Weight blocks (heads, FFN slabs) are treated as SLAM variables. Each batch adds a linearized factor (Kronecker-factored information plus residual) to a sparse square-root information matrix kept in fp32 in host RAM. Cross-block factors are kept only between blocks that are strongly co-activated. A Bayes tree updates only the affected cliques. A block's Jacobians are recomputed on a stored mini-sample only when its estimate drifts past a threshold; otherwise it is solved by cheap back-substitution. The GPU computes forward passes and Jacobian sketches, and the CPU does the sparse Cholesky updates. Each token's information is kept rather than fading out through momentum.
VALUE: It reaches a target loss on far fewer tokens than first-order training, which matters most when data is the binding limit.

A04
MECHANISM: Before training, a frozen 4-bit open-weight model makes one pass over the corpus and stores one number per 512-piece span in RAM: its own prediction error, in bits per piece. During training, the CPU keeps a short history of the small model's error on each span. It then computes two things: the gap (small error minus frozen error) and the slope (how fast that gap has shrunk over recent visits). Spans are sampled in proportion to gap times slope. Spans where even the frozen model's error is high are treated as noise and dropped, and spans whose gap has closed are retired. The frozen model never touches the small model's outputs or internal states. It only sets prices, so the weekly 5B-piece budget goes to content that can be learned but has not been learned yet.
VALUE: Each week's compute buys several times more learnable signal per piece than a model that sees the corpus uniformly or by plain error ranking.

A05
MECHANISM: One shared stack of layers feeds two readouts: one predicts the next piece left to right, and the other predicts the previous piece right to left. They are trained jointly on reversed and unreversed copies of the same spans, at almost no extra memory cost. During generation, the system samples several candidate continuations. For each one it measures how many bits the right-to-left readout needs to recover the prompt from that continuation, and it keeps the candidate that needs the fewest. During training, positions where the two directions assign strongly different probabilities to the same middle span get extra weight. This pushes the shared layers to hold facts that work in both directions instead of one-way surface habits. All of this fits easily on a 12 GB card, because the second readout is small and the checking is batched candidate passes.
VALUE: The model gets a built-in signal for spotting continuations that aren't supported by the prompt, and a forward-only model of the same size has no internal way to compute that.

A06
MECHANISM: A frozen small open-weight model parses text into hashed (subject, relation, object) triples. Up to about 500M of these sit in the 32 GB of RAM as integers, each with a truth bit and a pressure counter. Logical constraints are encoded as sparse incidence matrices: transitivity, one value per functional relation, mutual exclusion and type rules. The GPU counts the violated constraints in parallel. A Metropolis process flips truth bits, and its randomness is lowered over time until the total number of violations is at a minimum. To answer a query, the system reads the settled bits and the frozen model writes them out as text. Nothing is learned by gradients, and the GPU work is only sparse integer counting.
VALUE: It keeps a globally consistent belief store with hundreds of millions of facts that reconciles conflicting sources, which a 200M-parameter network can neither hold nor make consistent.

A07
MECHANISM: One shared network is trained to factorise each sequence both left-to-right and right-to-left, with a learned direction embedding selecting the order. A consistency loss penalises any disagreement between the two total sequence log-likelihoods, which must be equal for a coherent joint distribution. Disagreement on a sequence also flags it as a high-information sample, and those samples are reweighted in later epochs. The cost is about 1.6 times the compute per token, but every token gives two prediction targets plus a consistency constraint, which raises data efficiency within the 5B-token weekly budget.
VALUE: It removes the reversal curse ("A is B" implies "B is A") and gives better-calibrated probabilities over whole sequences, which a one-directional transformer trained on the same budget cannot achieve.

A08
MECHANISM: Three units share one tokenizer: a 200M student (baseload), a 1.5B open model (mid-merit) and a 4-bit 8B open model (peaker). A 5M forecaster reads the student's hidden state and predicts how much each unit would reduce loss over the next 16 tokens; it is trained by regression on logged realized reductions. A dual price λ is updated by subgradient so that compute spending clears the latency budget. A unit is committed only when its forecast gain is larger than λ times its running cost plus its startup cost (catch-up prefill of the tokens it skipped). A minimum up-time keeps the 8B's KV cache warm across hard spans, and it is idled across easy ones.
VALUE: It delivers near-8B quality on the hard tokens at about 2-3× the cost of the small model, a cost-quality point that no single same-budget transformer can reach.

A09
MECHANISM: Each entity and attribute mentioned in a long document gets a complex-valued oscillator, with up to millions of them in VRAM. Links found by a frozen small parser couple them. The GPU integrates the coupled phase equations, which is cheap elementwise work, so linked items fall into phase-locked clusters. Coupling strengths are raised or lowered according to how stably each cluster stays locked over time. To answer a question, the system reads which oscillators share a phase, for example who holds what or where something is.
VALUE: It tracks state and variable bindings across an unbounded document at linear cost, which is where a small fixed-context transformer breaks down.

A10
MECHANISM: The stored objects are edit operators: span-level rewrite transforms taken from aligned sentence pairs, such as a tense change, a negation or swapping roles. They live in RAM as typed diffs. The GPU composes operator pairs in bulk and checks whether each result matches an existing operator class. Classes are kept in a union-find structure that merges, and splits when a merge breaks closure. Generation applies chains of operators to retrieved exemplar sentences.
VALUE: It gives exact compositional and analogical generalization, applying any combination of known transformations to any sentence, instead of the approximate interpolation a same-budget network learns.

A11
MECHANISM: The residual stream is split into named subspaces such as tense, number, speaker, topic, numeric value and polarity. Training adds interchange-intervention losses: the model runs on a pair of inputs that differ in one factor, the matching subspace is swapped between the two runs, and the output must change exactly as the counterfactual text predicts. The counterfactual pairs are generated on the CPU by templated and rule-based perturbations of the corpus, for example number inflection, entity swaps and digit edits. That costs nothing on the GPU, and roughly every third training batch is a paired batch.
VALUE: The model generalises systematically, recombining factors in ways it never saw together, and it can be edited reliably by setting a subspace directly. An unconstrained same-budget transformer only gets there with far more data.

A12
MECHANISM: Next to a small transformer, the model keeps an explicit per-context graph of at most 64 entity slots, each with a typed attribute vector, plus a sparse relation matrix between slots. At each token a small controller emits discrete edit operations: create, bind, update attribute, add or remove relation, or no-op. These are trained with straight-through Gumbel estimates, so next-token loss reaches the operations through a graph readout that the decoder attends to. A small auxiliary loss rewards edits that make later references predictable, such as pronouns, quantities and possession changes. The graph is a few kilobytes per sequence and the controller adds about 5% compute, so this fits easily on a 3060.
VALUE: It gives exact, length-independent tracking of entities and state (who holds what after 40 transfers), which a 200M transformer can only approximate in its attention patterns and loses as the context grows.

A13
MECHANISM: The 64k vocabulary is arranged as a 256×256 grid. A ~150M local-context network predicts the row and column codes independently, conditioned on a deme chosen by a binary router tree, and each leaf of the tree owns a small low-rank modulation. The CPU keeps a joint-count table for each leaf in RAM (a few hundred MB) and computes the heterozygote-deficit statistic F from joint versus product-of-marginal frequencies. A leaf with significant F is split by 2-means over its routed hidden states, with the child adapters copied from the parent. Sibling leaves with F_ST ≈ 0 are merged. Two 256-way softmaxes replace the 64k softmax, which frees compute and VRAM for the base network.
VALUE: Output capacity and the number of experts grow exactly where the cheap independence assumption fails, so the model gets a large-vocabulary decoder for a fraction of the cost of a full softmax.

A14
MECHANISM: Attention scores are computed as q_iᵀ R_c k_j. Here c is a relation type chosen by Gumbel-softmax from a codebook of 64 small orthogonal block matrices. During training the model samples token triangles (i,j,k), measures the misclosure ‖R_c(i,j) R_c(j,k) − R_c(i,k)‖, and accumulates it per type triple, as in a surveyor's network adjustment. A type with persistent bimodal misclosure is split into two. A composition that consistently closes onto no existing type creates a new type initialized to the product of the two operators, and types never used in closed loops are deleted. The operators are tiny, so sampling triangles adds under 5% compute.
VALUE: The model builds a closed, compositional vocabulary of relations, which supports multi-hop relational generalization that a same-size transformer's unconstrained attention cannot guarantee.

A15
MECHANISM: A slot-based reasoning latent x is refined by Elser's difference map: x <- x + beta[P_A(f_B(x)) - P_B(f_A(x))]. P_A is a small transformer that projects onto logically consistent states. P_B projects onto knowledge-consistent states through Idea 1's decoder or a layer of a frozen quantized open model. Both are trained with an idempotence loss plus task loss, using implicit differentiation at the fixed point, so memory use stays constant however many iterations run. Iteration stops when the two projections agree. Each step is cheap enough to run hundreds of times on the 3060.
VALUE: It solves constraint-heavy multi-step problems where single-pass or single-loop models get stuck at wrong fixed points.

A16
MECHANISM: The base model attends only within a 256-token window, so it is fast and small. Periodically the CPU runs Granger F-tests on logged batches. For each pair of hidden-state cluster (out of 1024 k-means codes) and lag band, it tests whether that cluster appearing in that band explains variance in the current per-token surprisal residual, with Bonferroni correction. Each significant pair creates a "wire": a single-query head that attends only to the positions where that cluster fired inside that lag band, initialized from the regression coefficients. Wires whose Ljung–Box test later comes back white are pruned.
VALUE: Long-range dependencies use compute only where the data statistically requires them, giving long effective context that a same-budget dense-attention transformer has to truncate.

A17
MECHANISM: Each large weight matrix is never stored. It is rebuilt on the chip, block by block, as a weighted sum of K pseudorandom matrices, each fully determined by a 32-bit integer seed, plus a small dense correction. The card regenerates a block's values from a counter hash inside fast on-chip memory just before it multiplies with that block. Only the seeds, the mixing coefficients and the small correction are stored and updated by the prediction-error signal. Every few thousand steps, seeds whose coefficients have stayed near zero are swapped for fresh random seeds, so the basis is gradually searched rather than fixed. The card does about 70 arithmetic operations for every byte it can fetch, so trading spare arithmetic for scarce memory traffic and storage lets a network with roughly 10-20B virtual weights train and run in 12 GB, with update bookkeeping about 1000 times smaller.
VALUE: The width and depth of the network are set by the arithmetic budget instead of the 12 GB memory ceiling, which a stored-weight model of the same budget cannot escape.

A18
MECHANISM: Facts are stored as sparse binary words (8192 bits, 64 active). Together they form the null space of a large sparse constraint graph held in host RAM (10-20 GB of edge lists), learned incrementally with a Karbasi-style null-space rule over spans the model encodes from the corpus. At chosen layers the model emits a noisy partial word from its hidden state. The CPU runs 5-10 rounds of min-sum decoding to reach the nearest stored codeword, and a learned projection adds that codeword back into the residual stream. The query head is trained with a straight-through estimator. Decoding is sparse integer work on the CPU that overlaps with GPU compute, so capacity grows with code length rather than VRAM.
VALUE: It recalls whole facts from corrupted or half-given cues, at a capacity well beyond what 200M dense weights hold.
