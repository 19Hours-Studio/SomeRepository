**Offspring 1 (Pair 1: motion-compensated KV coding × incremental-smoothing estimation).** I keep the KV cache in compressed form but turn it into a smoothed estimate that can be corrected later. Each chunk's stored state is a variable in a sparse factor graph on the CPU. Keyframe chunks hold fp16 K/V, and the others hold low-rank residual coefficients. The motion vectors decide which cross-chunk factors exist, so the reference structure is also the sparsity pattern of the information matrix. In the other direction, the Bayes tree's marginal uncertainty, weighted by attention mass, drives the I/P choice and the residual rank. Suppose a late chunk strongly matches an old one, for example the same function body seen again. That match adds a loop-closure factor, and incremental re-solving updates only the affected cliques. Earlier chunks are then re-coded against the new keyframe, which cuts storage and removes drift that has built up along long reference chains.

**Offspring 2 (Pair 2: LDPC fact memory × Granger-wired lag heads).** The 8192-bit word is not an arbitrary fact code. It is a lagged-context signature: 1024 hidden-state clusters × 8 log-spaced lag bands, with a bit set if that cluster fired in that band. The parity checks are learned from training-corpus signatures, so they encode which long-range co-occurrence patterns are typical. At inference the 256-window model's signature is partial, because bands beyond the window are mostly unseen. Min-sum decoding fills in the bands it is most likely to need. Unsatisfied checks (the syndrome) are logged. A check whose violations Granger-predict the surprisal residual spawns a wire head over exactly those positions. Wires that later test white are pruned, and their pattern is folded back into the code as a new check. So the decoder proposes candidate dependencies, and the statistical tests decide which ones get compute.

**Honesty check**
- **Offspring 1:** The closest work is DeltaKV/KVTC (residual KV coding), B-frame bidirectional prediction, and keyframe pose-graph SLAM (iSAM2). None of these re-solves a compressed cache jointly and backward when a later match appears, or sets rate from posterior marginals. The mechanism is distinct, though it inherits the parent's KV-compression framing.
- **Offspring 2:** The closest work is Compressive/Memorizing Transformers, Hopfield-style memories over context summaries, and Routing Transformer. Those store or retrieve vectors and route by content similarity. Here the memory is an error-correcting code over lagged cluster patterns, and attention wiring is created from decoder syndromes by statistical tests. This is not a re-skin of NGRAMIDX (no corpus lookup), SLEEP or SSM.

=== IDEAS ===
IDEA 1
NAME: Loop-Closed KV Smoothing
MECHANISM: Context is coded in 64-token chunks: keyframe chunks keep fp16 K/V, and the others store a motion vector (reference chunk plus token alignment) and low-rank residual coefficients. Each chunk is a variable in a sparse square-root information graph kept in fp32 in host RAM. The motion-vector references set which cross-chunk factors exist, and reconstruction factors come from attention-output error on probe queries. When a new chunk's key sketch closely matches a distant chunk, a loop-closure factor is added, and an incremental Bayes-tree update on the CPU re-solves only the affected cliques. It re-codes earlier chunks against the new keyframe and pushes corrected residuals to the GPU. The rate controller reads the marginal covariances: uncertain, heavily attended chunks become keyframes or get higher rank, and well-constrained ones shrink to near-zero residuals. The GPU only reads small residuals and does no extra work.
VALUE: Million-token working memory in 12 GB whose compression error falls as more context arrives instead of building up, which neither a truncating transformer nor a one-pass KV codec can do.

IDEA 2
NAME: Syndrome-Spawned Lag Codes
MECHANISM: A 256-token-window base model builds, per position, an 8192-bit signature: which of 1024 k-means hidden-state clusters fired in each of 8 log-spaced lag bands. A sparse parity-check graph in host RAM (10-20 GB of edge lists) is learned from training-corpus signatures with a null-space rule, so valid codewords are typical long-range co-occurrence patterns. At inference, 5-10 rounds of min-sum decoding on the CPU complete the partial signature, and a learned projection adds the completed bands into the residual stream. Syndromes that stay unsatisfied are logged. When a check's violations pass a Bonferroni-corrected Granger F-test against surprisal, the system spawns a single-query wire head over exactly those cluster/band positions, initialized from the regression. Wires that later pass a Ljung-Box whiteness test are pruned, and their pattern is folded back into the code as a new check. All decoding and testing is sparse integer or statistical work on the CPU, overlapped with GPU compute.
VALUE: A small windowed model gets long-range structure recalled and error-corrected from corpus-wide constraint memory, plus exact attention only where tests show it reduces surprisal, so its long-range capacity is not capped by VRAM as a same-budget dense transformer's is.
