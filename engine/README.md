# Creativity engine

Инструмент, который превращает выводы исследования
(`research/stage1-creativity/`) в воспроизводимый процесс получения необычных и
ценных идей по любому трудному вопросу. Модели не вызываются из скрипта: `ce.py` —
детерминированное ядро (состояние, промпты, слепые наборы, разбор, отбор, пары,
отчёт), а субагентов запускает Claude по `.claude/skills/creativity-engine/SKILL.md`.

```
python3 engine/test_ce.py     # холостой самотест всех команд (без моделей)
python3 engine/ce.py -h       # команды: init prompt ingest set family judge select lit pairs remember report
```

## Почему процесс устроен именно так

| Шаг движка | Что его обосновывает (находка) |
|---|---|
| **Карта аттракторов из данных** (стадия 0: 3 простых прогона → судья кластеризует семейства) | Самомодели верить нельзя: Haiku предсказал 0 из 6 своих идей, Opus — около половины (F8). Аттракторы надо измерять |
| **Портфель техник** NEG / CORE / REFRAME / MECH / LOOP | Каждая техника уводит в свой бассейн; разнообразие популяции важнее «лучшего промпта» (F2, TL;DR-4) |
| **Нейтральный формат `VALUE`** вместо «что не умеют текущие подходы» | Старое поле тянуло к стандартному списку жалоб (спотыкание №1, F3) |
| **Никаких примеров в промптах** | Примеры копируются дословно (R4) |
| **Два слепых судьи + классификация по бассейнам** | Один судья ограничен знаниями (химсети: 6 у Sonnet → 2 у Opus); лексические метрики слепы к переодетым аттракторам (F3, F6) |
| **Литературная проверка выживших** | 13 из 13 «лучших» оказались частично или полностью известны; модели-судьи свежих работ не знают |
| **Эволюция: скрещивание из разных бассейнов + отталкивание от литературы** | Поднимает потолок O×V (25 → 36); отбор накапливает качество |
| **Память аттракторов** (`remember`): найденное становится запретным для следующего поколения | У каждого процесса свой аттрактор, включая «периферийные» (FLOW, SCALE) и мотивы родителей |
| **Иммиграция** (свежий прогон лучшей техники в каждом поколении) | Иначе инбридинг: потомки скрещивают одни и те же мотивы |
| **Техника LOOP** («диагностика зрелой науки + замкнутая петля») | Общий рецепт всех сильных кандидатов по литературной проверке. В исследовании как техника **не проверялась** — проверяется в финальном тесте |
| **Контроль best-of-N** | Отделяет вклад техник и эволюции от эффекта «много попыток + хороший фильтр» |

**Чего в движке нет и почему:** текстовой диффузии (провалилась и как просьба, и
при принуждении скриптом), случайных слов и лексических ограничений (поглощаются
моделью), внешнего запрета-списка без техники (уводит в L2), запрета важных целей
(убивает ценность).

## Ограничения
- Оценки дают модели того же семейства; литературная проверка неглубокая (2–3 запроса на идею).
- Различия между техниками при 3 идеях на прогон меньше разброса между запусками;
  надёжны только крупные эффекты.

## Валидация (финальный тест, `research/stage1-creativity/04-final-test.md`)

Новый вопрос, 8 генераций против 8 у best-of-N, тот же отбор, слепые судьи:
**O +2.41** (чистый судья без карты бассейнов: **+2.13**), **топ-3 O×V +12.2 (+10)**,
переоткрытия 0–1/24 против 5–6/24. Единственные NO-CLOSE-MATCH по литературе (3) — у движка.
Плата: средняя ценность V ниже на 0.5–0.8. Лучшая техника — **LOOP**; MECH — слабейшая;
эволюция (gen2) повышает O, но снижает конкретность.

## v2-опции и результат A/B (`research/stage1-creativity/05-self-improvement.md`)

Движок сам придумал, как себя улучшить (прогон `meta1`). Реализованы: ходок по пробелам +
техника GAP, скрининг без риторики, аудит переноса ценности + приманки (`gapwalk`, `gap`,
`strip`, `audit`, `select --v2`) и инструменты A/B (`fork`, `import`).
**A/B на новом вопросе: v2 не лучше v1** (O −0.2…−0.45, топ-3 O×V −7…−9; разница внутри шума запусков).
Причины: аудит одним судьёй ничего не различал (это мнение, а не измерение), а ослабленный
фильтр бассейнов дал слабых родителей. **По умолчанию — v1.** Следующие кандидаты (v3) —
только с настоящими выборочными измерениями (выводимость через свежих агентов, разрыв подсказки),
по одному изменению на A/B, с повторами.

## v1.5 (текущий вариант по умолчанию)

Лёгкая проба (15 агентов, общие судьи с v1): портфель neg, core, core, mech, loop (REFRAME убран как
стабильно слабейшая) + конкретизация потомков gen2 «первым тестом». Результат: **конкретность +0.9…+1.3
в среднем, +2.4…+3.1 у потомков**, оригинальность +0.3, ценность −0.2 (шум), 0/23 переоткрытий.
«Первые мысли» (самоотчёт) — опция `setcfg R thoughts 1`: эффект мал, потому что стадия карты
аттракторов и так измеряет «первые мысли» модели напрямую.

## v1.6-опция: эволюция видов (`breed`, `species`, `fitness`, `import-basins`)

Агент-селекционер скрещивает и мутирует шаблоны техник, уводя их от ниш, найденных в прошлых
прогонах. Новые «виды» лежат в `engine/species/`, родословная и приспособленность — в `species.json`.
`prompt` принимает имя вида так же, как имя шаблона. A/B против v1.5 (16 агентов, общие слепые судьи):
повторов находок v1 **на 15 п.п. меньше** (48% → 33%), но O −0.6, V −0.3…−0.4, топ-3 O×V −2.5…−4.3.
Проигрыш целиком приходится на новые виды (17.4 против 24.7 у заменённых техник), а общие техники
в обоих плечах равны. Причина: ниша LOOP была пиком ценности, а не ловушкой. Кроме того, аттракторы
наследуются через скрещивание и частично принадлежат самому вопросу.
**По умолчанию остаётся v1.5**, виды копят приспособленность на новых вопросах.
Повторы между прогонами одного вопроса снимает реестр: `import-basins R <прошлый> --source visited --as prior`
до gen1. Подробности: `research/stage1-creativity/05-self-improvement.md` §9.

## v1.7 (по умолчанию после A/B)

Разбор 8 прогонов (`research/stage1-creativity/06-engine-v17.md`) показал две главные слабости. Первая —
монокультура переноса («метод из далёкой области как надстройка»). Вторая — стабильный штраф по ценности
(−0.4…−0.8), потому что идеи обходят суть вопроса. v1.7: судья семейств называет **ядро вопроса (CRUX)**,
генераторы обязаны его атаковать (`setcfg R use_crux 1`), финальные судьи отмечают атаку ядра (`set --crux`).
Фрагменты отсеиваются, отбор разнообразный (`select --diverse`). Внешняя метрика: 13% проверенных идей
движка нашли себе «пару» в работах, вышедших после даты знаний модели.

**A/B v1.7 против v1.5** (общие слепые судьи, плюс «простой» судья без колонок ядра и G): V +0.8…+1.7, G +1.0…+1.1, C +0.5…+1.0,
O −0.6…−0.7; штраф по ценности относительно контроля сократился с −1.05 до −0.26. Упрощающее скрещивание (`evo_simple`)
развернуло падение гениальности во втором поколении. Половина прироста V у судей с колонкой ядра — подсказка
(урок: всегда держать судью, не видящего, в чём состоит лечение). Следующее (v1.8): ядро как ограничение, а не цель.

## v1.8-L: слои (по умолчанию; идея пользователя)

Слой A (оригинальность) — генерация как в v1.5. Слой B (гениальность + ценность, команда `valorize`): агент называет
у каждой идеи **якорь** (необычный механизм), перестраивает идею вокруг якоря так, чтобы она справлялась с ядром
вопроса, и упрощает до одного хода. A/B на 23 идеях: O +0.7 (ни одна идея не потеряла оригинальность), G +1.0,
переоткрытия 4 → 0, O×V лучший у обоих судей; V почти не изменилась (+0.05 у простого судьи). Следующий кандидат — слой C «ценность».

## v1.8: слои A → B → C (по умолчанию)

Слой C «ценность» (`prompt_value`) называет способность и пользователя идеи, находит главное «узкое место» и превращает
надстройку в то, что архитектура сама вычисляет. Парная проверка: V +0.2…+0.3, ни одна идея не потеряла ценность,
O и G сохранились. Итог A→B→C: ценность и гениальность как у v1.7, оригинальность на +1.4 выше. Плюс бандит
по техникам (`ce.py portfolio`), метрика «предсказание будущего» (`ce.py futurematch`) и экономия судей
(один с колонками плюс один простой).

## v1.9: слой D «счёт» (`fermi`) и колонка реализуемости F (кандидат по умолчанию для вопросов о физическом мире)

Полный прогон v1.8 на вопросе вне ИИ (дешёвое хранение энергии на дни и недели,
`research/stage1-creativity/07-v18-full-run.md`) повторил эффекты слоёв (A→C: O +1.04, V +0.65, G +1.00, ни одна идея
не потеряла V). Но проверка на порядок величины показала, что судьи не ловят физически мёртвые идеи: в TOP3 у каждого
судьи оказалась идея, которая ошибается на порядки. Причина в определении V: «если бы сработало, насколько важно».
Слой D (`prompt_fermi`, разбор через `valorize R <set> --arm ED`) для каждой идеи находит ОДНУ величину,
которая решает, работает ли идея, считает её на конверте с явными числами, ищет закон масштабирования и ставит вердикт
PASS/FIX/FAIL с переделкой (для FAIL — честное сужение заявки). Поля `verdict` и `estimate` сохраняются.
Колонка F (`set ... --feasible`): судья сам делает проверку на порядок и ставит реализуемость 1–10.

Результат на 23 идеях слоя C: 0 PASS, 16 FIX, 7 FAIL. Вердикты совпали с независимым ручным счётом во всех 4
заранее записанных случаях, и независимый судья F согласен (F у родителей FAIL 1.9, у родителей FIX 2.9).
В парах: F +1.00, C +2.2…+2.4, O −0.22, V −0.1…−0.2 (у FIX V +0.3, у FAIL −1.0: заявки честно сужены).
Ожидаемая ценность O·V·F/10: 6.5 → 8.5 (+31%), лучшие три 11.0 → 14.4. Все три агента D независимо вывели общий
закон: «доля перетока × омические потери = nFDc/σ» не зависит от толщины разделителя, разделяет только отношение
подвижностей. Ни генерация, ни судьи этого не нашли.

## v3: движок, который спрашивает реальность (`engine/reality/`, `research/stage1-creativity/08-reality-engine.md`)

Единый принцип: **новизна дешёвая, истина дорогая — сделай истину дешёвой и спрашивай реальность много раз.**
Идея = программа, судья = запуск. Два полигона:
- `reality/arch/` — 4 способности (поиск по ключу, копирование, чётность, двухшаговая композиция) на обучающей и
  двойной длине. Учебный полигон, решён на 1.000 слепым глубоким проектом.
- `reality/lm/` — открытый полигон: посимвольная модель кода Python, ≤150 тыс. параметров и ≤300 тыс. элементов
  буферов, 3000 шагов на одном ядре, мера — бит/символ. Известные архитектуры: 1.95–2.03; одиночные агенты: плато
  1.78; **агент-исследователь с инструментами (38 опытов): 1.681**.
Цикл: `evo.py prompt R --method blind|dissolve|transfer|count|cross [--parents a,b]` → агент → `evo.py ingest` →
`evo.py eval CAND --seeds 0,1` (4 ядра) → `evo.py status`. Код родителей по умолчанию не показывается (якорит;
`--code` включает). Режим исследователя: `reality/lm/research_agent/TASK.md` — один агент с Bash делает десятки
дешёвых проверок сам. По данным это лучшая конфигурация.
